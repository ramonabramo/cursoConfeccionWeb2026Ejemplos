Ejercicio 11 - Demostración Empírica del Event Loop (setTimeout con 0 Milisegundos)

Comprende por qué setTimeout(fn, 0) NUNCA se ejecuta de inmediato: el viaje por las Web APIs, la Cola de Tareas (Task Queue) y la regla de oro del Event Loop.

Ejemplo Teórico Guiado
console.log("1. Síncrono inicio"); setTimeout(() => { console.log("2. setTimeout con 0ms"); // ¿Se ejecuta aquí? ¡NO! Va a la Task Queue }, 0); console.log("3. Síncrono final"); // Resultado en consola: 1 -> 3 -> 2

🔍 ¿Por qué el mensaje 3 se imprime después del 2 a pesar de tener 0 milisegundos?

  1. Call Stack (Pila de Ejecución): El motor de JS ejecuta primero todo el código síncrono línea por línea sin interrupción.
  2. Web APIs: Al ver setTimeout(..., 0), JavaScript no lo ejecuta; se lo delega al navegador, que inicia el cronómetro.
  3. Task Queue (Cola de Macrotareas): Al vencer los 0ms, la función callback entra en la cola de espera.
  4. Event Loop: Vigila incansablemente. Solo cuando la Pila de Ejecución está completamente vacía (después del último console.log síncrono), transfiere la tarea de la cola a la pila.
